# LyricMate：需求与设计

本文件为公开文档候选，不代表代码仓或安装包已完成发布审查。

## 产品范围

LyricMate 是面向 macOS 的独立歌词工具，读取已运行的 Spotify 桌面客户端的播放信息，在菜单栏和透明悬浮窗中呈现逐行同步歌词。歌词来源与音乐播放分离，不提供音频下载，不需要获取 Spotify 登录 Cookie。

部分代码和设计源于 [Lyric Fever](https://github.com/aviwad/LyricFever)。公开分发应保留原有 MIT 许可证、版权声明及适用的第三方归属；独立工具与上游发行版的名称、能力和支持渠道应明确区分。

## 功能需求

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| R1 | 跟随当前播放 | 获取歌曲、歌手、专辑、时长、播放状态和进度；切歌立即隔离旧结果，断连不继续伪装实时高亮 |
| R2 | 渐进选择歌词 | 有效时间轴候选按当前最高分先载入，后到更高分替换，同分稳定；人工选择、偏移及重核验记忆优先 |
| R3 | 容错检索 | 支持只填歌名；精确查询无对应候选时在预算内补搜歌名，保留来源错误，不把请求失败等同于没有歌词 |
| R4 | 非阻塞匹配提示 | 歌手、时长或版本不确定的结果可以临时显示，但明确提示；匹配分不是同步准确率，不自动当成已确认录音保存 |
| R5 | 紧凑桌面呈现 | 显示当前句与下一句，无标题或底板；优先加宽，超长文本按语言边界换行，保持原时间块 |
| R6 | 自然过渡与进句提示 | 正常换句从下向上推进；前奏显示进句提示和首句；跳转、断连和减少动态效果采用适当的直接更新 |
| R7 | 显式播放控制 | 菜单和悬停控件提供播放／暂停及切歌，菜单提供前后跳转；点击即时反馈，指令返回后安全回读，不乐观伪造播放器状态或自动重试控制 |
| R8 | 设置与本地歌词 | 正常重启恢复连接偏好、悬浮配置、位置和来源设置；支持本地 LRC、备份及录音选择重核验，不导出个人配置作为产品默认数据 |

## 技术选择

- SwiftUI 负责工作台与设置；AppKit 的 NSPanel 和原生文本宿主负责透明浮层、悬停、测量和排版。
- Swift Concurrency 和主执行器组织会话状态；播放器读取与控制共用串行执行队列和单飞约束，避免超时后重复系统事件。
- ScriptingBridge／Apple Events 与已运行的 Spotify 通信；系统权限由用户授权，不自动启动播放器或扩大权限。
- Foundation HTTP 适配歌词来源，通过受限清单与固定适配器调用接口；不加载可执行音源脚本，不绕认证或付费限制。
- 歌词搜索、录音评估、时间轴和呈现策略分层；`canPreview` 与录音可靠性分开，避免把“显示成功”误认为“原唱版本正确”。
- 时间轴、候选排序、控制门禁与恢复策略使用离线合成测试；后续原生界面验收应使用虚拟播放器与拦截 HTTP，不依赖真实账户数据。本源码候选尚未完成首次启动与系统权限验收。

## 关键权衡

**响应速度与版本准确性。** 搜索无需等待所有来源完成，但低置信度候选可能属于翻唱、现场或器乐版。临时显示、可见提示和人工覆盖共同管理风险，不能把分数解释为准确概率。

**轻量呈现与可读性。** 透明双行减少遮挡；加宽优先于拆句，换行不创建新时间轴。长句、双语、缩放与减少动态效果需有独立测试。

**故障恢复与操作安全。** 截止时间不代表底层系统事件已取消。旧操作仍在途时不叠加读取／控制，保留关联诊断并停止失效高亮。

**日志与数据最小化。** 自动诊断应有界保留，不记录歌词正文或凭据。含歌曲元数据的手动导出应明确提示分享风险，不默认上传。

## 边界与发布约束

当前范围为逐行歌词，不承诺逐字演唱重音、吸气标注或人工听感校准。歌词呈现、录音身份和实际同步质量分别验收。

歌词和第三方接口的技术可访问性不等于内容再分发授权或服务承诺。公开源码、内置来源默认策略和安装包分发应分别审查；不得附带未获许可的歌词库、用户记录或服务凭据。可用性、限流及地区差异应在对应适配器说明中披露。

面向普通用户的 macOS 发行还需独立的签名、公证、首次安装和升级验证；开发环境中的构建与测试不能替代这些门槛。
