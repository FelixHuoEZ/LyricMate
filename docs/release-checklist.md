# Alpha 发布检查

以下是发行门槛，不是已完成声明。源码发布与普通用户安装包分别验收。

1. 复核 `release-files.txt` 与最终树；不包含历史仓、个人资料、诊断、账户配置、缓存、歌词库或未许可媒体。
2. 使用本地成熟秘密扫描器扫描最终树与全部拟公开 refs；用仓库外的私有词表复核身份与本机路径。扫描报告不提交。当前树通过不能替代历史／元数据检查。
3. 保留 LICENSE、NOTICE、解析器 MIT 和图标许可；核对每个外部服务的许可、地区及速率条款。维护身份与反馈说明已列在 CONTRIBUTING／SECURITY；正式 Bundle ID 和私密安全渠道实际启用需分别确认。
4. 在不带私人配置的环境运行严格离线测试和应用构建；另做首次启动、系统权限允许／拒绝、菜单／浮层、设置恢复、卸载与升级验证。离线通过不等于真实播放器或人工听感通过。
5. 按文件白名单导出源码归档，解包复核内容并再扫秘密。核对二进制 strings、签名身份、权限与附带许可证，将验证记录绑定最终文件 SHA-256。不要打包整个工作目录。
6. 普通用户安装包需单独完成 Developer ID、hardened runtime、签名、公证及 Gatekeeper 验收；[Apple 发行说明](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)。ad-hoc 产物不是公证发行包，不要求用户关闭系统安全保护。
7. 确认精确托管账号、仓库、公开范围和版本；仅在明确批准后创建远端、推送或上传。不要将私人父链、检查点 refs 或签名证书带入新公开仓。

开发者工具：`python3 scripts/public-source.py check` 检查清单完整性；`archive` 仅按清单打包，不包含 `.git`、构建输出或配置。脚本不能替代内容审查。依赖或源码发生变化后重新扫描与构建，不能沿用旧版本放行结论。

## 当前源码候选的范围

- P4.1：LRCLIB 请求身份、跨客户端串行间隔和 429 冷却；离线测试包括取消后恢复、域名边界和默认间隔。
- P4.2：五个平台不提供一键添加、启用或测试；运行注册器同样拒绝，旧保存数据不删、不改键。实现及原有历史保留，不把禁用运行说成彻底移除代码或授权已完成。
- P4.3：新增代码及图标许可范围和来源明确，不捆绑歌词库。商标／图形排他权未核准，商用推广前另做检索。
- P5.1：只读 CI、严格离线测试、双语检查、白名单、脱敏反馈和本地成熟秘密扫描。启用跟随前告知联网；可预览只含类别／耗时的脱敏诊断，详细本地诊断需另行确认。
- P5.2：源码归档在干净目录解包、重跑测试和完整构建，核对图标、签名与许可证；只证明本机构建，不等同安装发行。

这些是可测试交付定义，不是每次运行自动完成的声明。验收记录在仓库外私有保存，避免提交本机路径、检查命中和个人环境；不修改日常应用或原配置。

## 批准公开时再执行

以下操作不由构建、测试或扫描脚本自动执行，当前不要求改公开：

1. 对最终提交／全部拟发布 refs 和归档重新扫描，确认保留的历史与实验代码公开范围。
2. 明确批准精确仓库的可见性后，再改公开；随后启用 GitHub 私密漏洞报告并回读真实表单。SECURITY 链接存在不等于可用，私有仓 404 不当作已启用。
3. 回读 secret scanning、push protection 和分支保护的实际可用性与状态；套餐／接口不可用时保留未知，不声称测试脚本代替服务端保护。
4. 提交并同步后确认 GitHub 托管 CI 首次运行结果。本地同项通过不代表已经触发托管工作流，不上传原始扫描报告。
5. 名称／图形商用审查与签名安装包发行分别批准，不要求用户关闭 Gatekeeper，不附带普通安装包。

权利边界仍未知的内容，不宣传“全平台授权”“官方合作”或商业可用；源码代码许可不是歌词展示／再分发许可。若需上述承诺，应先取得适用的正式权利证明。
